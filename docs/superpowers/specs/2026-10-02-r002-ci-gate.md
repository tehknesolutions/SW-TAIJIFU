# R002 — CI Gate Design Spec

## Intent
Make GitHub Actions the objective verification gate for runtime pull requests so source changes are not treated as verified until tests and production build pass remotely.

## Approved design
For every pull request, run one minimal CI job:

`checkout → Node LTS → install → test → build`

## Behavior
- Trigger on `pull_request`.
- Use Ubuntu hosted runner.
- Use current Node LTS (22) for deterministic project verification.
- Install dependencies from the repository manifest. Until a lockfile exists, use `npm install`; once a lockfile is committed, migrate the workflow to `npm ci`.
- Run `npm test`.
- Run `npm run build`.
- Any failed step fails the CI job and blocks treating the PR as verified.
- No deployment, secrets, external paid services or environment-specific dependencies are part of R002.

## Success criteria
1. Workflow exists in `.github/workflows/ci.yml`.
2. A pull request commit triggers the workflow.
3. Test and build results are visible as GitHub Actions evidence.
4. If the current runtime has compile/test defects, R002 exposes them rather than hiding or bypassing them.
5. Fixes follow the observed CI logs until the job is green.

## Boundary
R002 establishes verification infrastructure. It does not by itself prove R001.1 green; the actual workflow run on PR #145 provides that evidence.
