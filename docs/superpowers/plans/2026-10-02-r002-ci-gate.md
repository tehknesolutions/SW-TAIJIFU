# R002 CI Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish GitHub Actions as the objective test/build gate for SW-TAIJIFU runtime pull requests.

**Architecture:** A single repository-native workflow runs on pull requests using an Ubuntu hosted runner and Node 22. It installs dependencies, runs the Vitest suite, then produces the Vite production build; GitHub Actions run/job logs become the verification evidence.

**Tech Stack:** GitHub Actions, Node.js 22, npm, Vitest, Vite.

**Spec:** `docs/superpowers/specs/2026-10-02-r002-ci-gate.md`

## Global Constraints
- Trigger on `pull_request`.
- Use `ubuntu-latest`.
- Use Node 22.
- Use `npm install` until a lockfile exists; migrate to `npm ci` after lockfile adoption.
- Run `npm test` before `npm run build`.
- Do not add deployment, secrets, paid services or environment-specific dependencies.

## Review Focus
- Workflow syntax must be accepted by GitHub Actions.
- Node/npm setup must match the repository runtime.
- Test failure must stop the job before a false green result.
- Build failure must fail the job.
- CI must trigger on PR #145 after the workflow commit reaches its head.
